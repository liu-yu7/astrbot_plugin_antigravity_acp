# 排障指南

## `/agy` 提示权限不足

`/agy` 是 AstrBot 管理员指令。发送 `/sid` 取得发送者 ID，在 WebUI 的管理员 ID 配置中添加并保存。WebUI 聊天使用登录用户名作为发送者 ID；不要填完整会话标识。

只在可信私聊或 WebUI 中完成登录，不要把授权码发到群里。

## `[PREFLIGHT]`：512K 不可用

默认 512K 需要完整本地补丁和可信检查脚本。检查：

1. agy 是否已安装、可执行且版本符合要求。
2. `patch_script` 是否是本机绝对路径，AstrBot 用户能否读取。
3. 脚本的 dry-run 是否支持当前二进制并报告全部六处补丁。
4. 自定义回放预算是否超过当前允许的字节上限。

没有补丁时，将插件窗口设为 **256K**，回放预算设为 **0**。不会影响正常登录流程。详见 [CONTEXT.md](CONTEXT.md)。

## `[AUTH]` 或登录后仍无法请求

执行 `/agy login`，完成浏览器授权，再发送 `/agy code <授权码>`。终端登录应使用运行 AstrBot 的同一个系统用户。

插件会复制文件型官方凭据给隔离 CLI 使用；SSH / systemd 用户如果不能访问桌面凭据库，可能需要官方 CLI 的文件型凭据回退。Linux 下可参考 README 的 `DBUS_SESSION_BUS_ADDRESS` 示例。

不要直接把 token 内容发给机器人、Issue 或第三方服务。

## 网络、代理或限流

- 不能直连 Google 时，给提供商源设置 `proxy`。
- 代理仅对官方 CLI 子进程生效；本机 MCP 地址通过 `NO_PROXY` 排除。
- `[QUOTA]` / `[RATE_LIMIT]` 与上游额度、负载有关，扩大上下文不会消除它们。
- `RESOURCE_EXHAUSTED (429)` 只证明当前请求被上游资源限制拒绝，不能仅凭它断言账号总额度耗尽。插件会停止重复提交明确被拒绝的请求，由 AstrBot 按原备用配置处理。
- 先核对 `/agy status` 的版本、代理、登录状态和最近错误。

## 短请求成功，完整请求却报 429

先区分“Provider 可用”“Gemini 短请求成功”和“完整 AstrBot 请求成功”。最终由备用模型回答，不能算 ACP 恢复。

已复现：AstrBot 4.29.4 的默认 Linux 本机工具提示段落，在部分完整请求中触发上游 429。适配器只对这一完整已知模板使用等价表达，保留角色文件/执行权限、POSIX 语法、托管会话操作、`write_line` 的真实换行，以及禁止 `&` / `nohup` / 脱离托管会话的约束。技能、角色与工具规格不移除。未知自定义模板及未验证系统不猜测。

若仍报错，比较最小输入和完整请求，检查实际发送的系统内容与工具配置；不要通过关闭安全设置、删掉角色或不停重试来掩盖问题。

## `Agent execution terminated`，日志中的工具参数 `enum` 报 400

这条通用错误不表示账号退出。先查看对应工作进程的 `acp.log.<PID>`；如果出现 `INVALID_ARGUMENT (code 400)` 和 `parameters.properties[...].enum[0]: cannot be empty`，检查实际工具 schema。

已在 agy 1.5.8 复现：合法的数字枚举 `enum: [0]` 在 Gemini 转换中变成空字符串，导致整次请求被拒绝。动态记忆工具的 `limit` / `excerpt_offset` 可能带有这种单值约束；无需关闭记忆工具或更换主模型。

更新并热重载适配器。MCP 声明保留数字类型，用等价上下界表达单值数字枚举；上游不支持的其他枚举保留在完整系统工具约束中，原宿主 schema、实际工具校验和权限不改。普通非空字符串枚举原样保留。独立 WebChat 验收时应禁用测试会话的备用，避免把 GPT 回退成功误当 Gemini 修复成功。

## 完成的请求仍占用会话或留下大量工作进程

更新适配器并热重载插件。适配器现在会在交出工具调用或最终回复之前关闭该步异步流，及时释放锁；停留中的工具回合仍保留，直到 AstrBot 返回工具结果。不要因此重置聊天数据库或重启 QQ 平台。

## 首次请求慢

冷启动包括进程初始化、模型列表读取和会话建立，可能需要数秒或更久。后续多轮通常复用会话。扩大窗口、图片和大量工具说明也会增加成本和内存需求。

## 保存后对话被中断

保存插件配置会热重载并停止旧进程，这是应用新设置的方式。尽量在没有生成任务时保存；下一次请求会按 AstrBot 历史重建。

`/agy reset` 丢弃 ACP 会话，不删除 AstrBot 持久化聊天历史。`/agy restart` 停止进程，下次请求重新启动。

## 日志与问题报告

agy 前端日志位于 `<agy_home>/acp.log`，每个工作进程的具体上游错误位于 `<agy_home>/acp.log.<工作进程PID>`。使用 systemd 时也可查看：

```bash
journalctl -u <你的AstrBot服务名> --no-pager
```

报告问题请附：插件版本、AstrBot 版本、agy 版本、系统 / 架构、所选窗口、脱敏后的错误和最短复现步骤。不要附完整运行目录或原始凭据。

## 已知边界

- 其他 AstrBot 版本、平台和模型组合尚未全部验证。
- 没有音频输入，`temperature` / `top_p` 不通过 ACP 控制。
- Token 用量按 ACP 回合返回值归一化，不是精确的每次内部模型调用明细。
- 回放按文本字节预算保留最近历史，不保证长历史完整或满窗质量。
