# 排障指南

## `/agy` 提示权限不足

`/agy` 是 AstrBot 管理员指令。发送 `/sid` 取得发送者 ID，在 WebUI 的管理员 ID 配置中添加并保存。WebUI 聊天使用登录用户名作为发送者 ID；不要填完整会话标识。

只在可信私聊或 WebUI 中完成登录，不要把授权码发到群里。

## `[PREFLIGHT]`：512K 不可用

默认 512K 需要完整本地补丁和可信检查脚本。检查：

1. agy 是否已安装、可执行且版本符合要求。
2. `patch_script` 是否是本机绝对路径，AstrBot 用户能否读取。
3. 脚本的 dry-run 是否支持当前二进制并报告全部六处补丁。
4. 自定义回放预算是否超过当前允许的字节上限。

没有补丁时，将插件窗口设为 **256K**，回放预算设为 **0**。不会影响正常登录流程。详见 [CONTEXT.md](CONTEXT.md)。

## `[AUTH]` 或登录后仍无法请求

执行 `/agy login`，完成浏览器授权，再发送 `/agy code <授权码>`。终端登录应使用运行 AstrBot 的同一个系统用户。

插件会复制文件型官方凭据给隔离 CLI 使用；SSH / systemd 用户如果不能访问桌面凭据库，可能需要官方 CLI 的文件型凭据回退。Linux 下可参考 README 的 `DBUS_SESSION_BUS_ADDRESS` 示例。

不要直接把 token 内容发给机器人、Issue 或第三方服务。

## 网络、代理或限流

- 不能直连 Google 时，给提供商源设置 `proxy`。
- 代理仅对官方 CLI 子进程生效；本机 MCP 地址通过 `NO_PROXY` 排除。
- `[QUOTA]` / `[RATE_LIMIT]` 与上游额度、负载有关，扩大上下文不会消除它们。
- 先核对 `/agy status` 的版本、代理、登录状态和最近错误。

## 首次请求慢

冷启动包括进程初始化、模型列表读取和会话建立，可能需要数秒或更久。后续多轮通常复用会话。扩大窗口、图片和大量工具说明也会增加成本和内存需求。

## 保存后对话被中断

保存插件配置会热重载并停止旧进程，这是应用新设置的方式。尽量在没有生成任务时保存；下一次请求会按 AstrBot 历史重建。

`/agy reset` 丢弃 ACP 会话，不删除 AstrBot 持久化聊天历史。`/agy restart` 停止进程，下次请求重新启动。

## 日志与问题报告

agy 日志位于 `<agy_home>/acp.log`。使用 systemd 时也可查看：

```bash
journalctl -u <你的AstrBot服务名> --no-pager
```

报告问题请附：插件版本、AstrBot 版本、agy 版本、系统 / 架构、所选窗口、脱敏后的错误和最短复现步骤。不要附完整运行目录或原始凭据。

## 已知边界

- 其他 AstrBot 版本、平台和模型组合尚未全部验证。
- 没有音频输入，`temperature` / `top_p` 不通过 ACP 控制。
- Token 用量按 ACP 回合返回值归一化，不是精确的每次内部模型调用明细。
- 回放按文本字节预算保留最近历史，不保证长历史完整或满窗质量。
